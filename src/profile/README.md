# profile：选项到计算画像

这一层的职责只有一件事：把页面上的选择题换成一组可以直接进计算引擎的数字。

## 为什么单独一层

页面提交的是选项，`pension`、`living`、`lifecycle` 需要的是金额与年龄。如果没有
这一层，每个命令都要各自写「1.2 万到 2 万」对应多少钱，档位一变就到处改。
现在只有这里知道档位，下游只吃 `Profile`。

## 文件

- `tiers.py`：档位表。每个选项给出 `value`（提交用）、`label`（界面文案）、
  `amount`（计算取值）与区间端点。取值是区间中值；开口档取代表值。
- `derive.py`：推导。养老金四个参数（年限、缴费指数、个人账户余额、计发基数）、
  法定退休年龄、规划终点（寿命 75% 分位）。
- `schema.py`：`Profile` 与 `PensionParams`，冻结 dataclass，构造时校验区间与配比。
- `build.py`：`build_profile()` 把选项串成 `Profile`；`tier_amount()` 给命令层复用。

## 口径

- 档位取值与界面文案的唯一来源是 `tiers.py`，页面清单只引用 `value`
- 养老金参数按 `docs/data-sources.md` 的口径推导，记账利率默认 1.5%
- 计发基数用全国月均工资乘城市系数，标 `[待核]`；待分城市工资数据到位后只改
  `BASE_MONTHLY_WAGE` 与 `city_base_wage()`
- 默认配比 高 30% / 中 50% / 低 20%，由 `portfolio` 解释成收益与波动

## 测试

`src/tests/test_profile.py` 覆盖：档位不重复且落在区间、未知选项报错、缴费年限
封顶、缴费指数夹紧、账户余额复利、三种性别的法定退休年龄、构建画像与校验失败。
